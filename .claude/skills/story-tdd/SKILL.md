# TDD по истории

На входе номер истории и сценария из `docs/user-stories.md`, например «US-23, сц. 2».
Тест пишем по сценарию, а не по коду: «Тогда» сценария — это и есть утверждение теста.

## Порядок

1. **Прочитай сценарий.** Если его «Тогда» нельзя проверить без спора («понятно»,
   «заметно», нет числа), сначала правь историю, а не код, и скажи об этом Славе.
2. **Напиши тест там, где его увидит пользователь.**
   - Экран и путь пользователя — **E2E на Playwright**, это основной вид теста:
     `frontend/e2e/us-NN-<слово>.spec.ts`, один файл на историю, один `test()` на
     сценарий. Название теста — дословно название сценария:
     `test('US-23 сц. 2: сохраняется любая настройка', …)`. Образец —
     `frontend/e2e/us-03-menu.spec.ts`.
   - Ответ API без экрана — тоже Playwright, фикстура `request`, в той же спецификации
     истории: `const r = await request.put('/api/settings/order_threshold_a', …)`.
   - Логика экрана без браузера — `*.selfcheck.ts` рядом с экраном, запуск `node <файл>`.
   - Расчёт и данные — `code/tests/test_*.py`.
3. **КРАСНЫЙ.** Запусти тест до правки: `cd frontend && npx playwright test e2e/us-NN-*.spec.ts`.
   Он обязан упасть **по причине из сценария** — например, `Expected: 200, Received: 500`.
   Упал из-за опечатки в селекторе или таймаута загрузки — это не красный, чини тест.
   Сохрани строки `Expected`/`Received`.
4. **Проверь, что тест умеет падать**, если он зелёный с первого раза (сценарий уже
   работает): подмени ожидание на заведомо неверное, увидь падение, верни. Зелёный
   тест, который не умеет краснеть, ничего не доказывает.
5. **Правка** — минимальная, по ponytail. Экран правишь — смотришь и консоль браузера.
6. **ЗЕЛЁНЫЙ.** Та же команда, тот же тест. Сохрани вывод.
7. **Выкладка.** E2E ходит на стенд, поэтому зелёный он станет только после выкладки
   правки. Коммит фронта — ещё не выкладка: `dist` едет отдельно (`docs/server.md`).
8. **Запиши прогон** строкой в таблицу «Результаты прогона» в конце
   `docs/user-stories.md`: история и сценарий, роль, красный вывод, зелёный вывод,
   команда, что мешало пользователю.
9. **Коммит** — один на историю, когда тест зелёный, и только по «да» Славы.
   Текст предложи. В `master` красный тест не коммитим: все сессии работают в одной
   ветке, и красный `master` ломает соседей.

## Запуск

```bash
cd frontend
npx playwright test                               # все истории против стенда
npx playwright test e2e/us-03-menu.spec.ts        # одна история
E2E_LOGIN=admin1 npx playwright test e2e/us-23*   # под другой ролью
BASE_URL=http://localhost:5173 npx playwright test  # против локального vite
E2E_CHROMIUM=/opt/pw-browsers/chromium npx playwright test  # облачная сессия
npx playwright show-trace test-results/<папка>/trace.zip   # разбор упавшего
```

Конфигурация — `frontend/playwright.config.ts`: стенд `https://moskollektor.mbogatyreva.ru`
по имени: голый IP облачный прокси не пропускает (403). `ignoreHTTPSErrors` стоит
ради облачной сессии — её прокси подменяет сертификат стенда своим, и без флага
Chromium отвечает `ERR_CERT_AUTHORITY_INVALID`. Заголовок `X-User-Login` берётся
из `E2E_LOGIN`, по умолчанию `dispatcher1`; трасса сохраняется у упавших тестов.

В облачной сессии (claude.ai/code) стоит Chromium сборки 1194, а Playwright 1.63
ищет 1243 и падает на `browserType.launch: Executable doesn't exist`. Там запускаем
с `E2E_CHROMIUM=/opt/pw-browsers/chromium`; `playwright install` не делаем.

**Выкладка из облачной сессии — PR на каждую историю** (решение Славы 27.09.2026):
ветка → PR → Слава вливает в master → Actions выкладывает на стенд → тот же тест
зелёный. Пока PR не влит, тест против стенда зелёным не станет.

## Чего не делаем

- **Процент покрытия строк.** Он считает выполненные строки, а не прошедшие сценарии:
  тест на `precision_min` выполняет строку `settings.py:36` на 100 %, а для
  `order_threshold_a` та же строка отвечает 500. Меряем число зелёных сценариев.
- **Коммит на каждом шаге.** Красный коммит в общем `master` ломает соседние сессии.
  Доказательство «было красным» лежит в таблице прогона, а не в истории git.
- **Jest и jsdom.** Эмулятор не видит вёрстки: 49 слипшихся меток на оси пикетов
  нашлись только в настоящем браузере.
- **Тест против мока.** Мок отвечает по контракту, стенд — по факту, и расходятся они молча.
