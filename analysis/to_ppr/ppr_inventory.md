## 2. Структура листа

Титул (A7, объединено A7:H7): *«Приложение к план-графику планово-предупредительных
работ (ППР) аппаратуры контроля метана на 2026 год»*.

Шапка — **одна строка (9)**, восемь колонок A–H. Данные — **26 строк (10–35)**,
по одной строке на «Наименование коллектора».

Ключевая вёрстка — **объединённые ячейки**:

* `A10:A35` — подразделение «РЭК» на весь блок данных;
* `B…` — месяц: одна ячейка месяца покрывает 1–4 строки-объекта
  (напр. `B19:B22` «Май» → 4 объекта);
* `E/F/G/H` — даты четырёх этапов работ: **один «пакет» работ охватывает 1–4 объекта**
  (напр. `E19:E22`+`F19:F22`+`G19:G22`+`H19:H22` — четыре объекта на общих датах);
* исключение — колонка H («Сдача работ по ППР комиссии») в трёх пакетах
  не объединена: у объектов внутри пакета своя дата приёмки
  (P01: 27.01 и 28.01; P11: 19.08 и 21.08; P13: 07.10 и 08.10).

Итого **16 пакетов работ** на 26 объектов (группировка — по объединению ячеек колонки E).

## 4. Семантика работ

Один цикл ППР по объекту — четыре последовательных этапа:

1. **Демонтаж датчиков метана** (E) — датчики физически снимаются;
2. **Сдача датчиков в ОМ** (F) — на ППР **и поверку** (ОМ — по контексту отдел
   метрологии/механизации, расшифровки нет) — следующий рабочий день;
3. **Вывоз датчиков из ОМ** (G) — возврат после ремонта/поверки;
4. **Сдача работ комиссии** (H) — приёмка.

Хронометраж одного пакета (от демонтажа до приёмки): **13–25 дней**
(мин. P06 — 13, макс. P09 — 25, медиана 17). Внутри окна: 7–16 дней датчики
находятся в ОМ (ремонт+поверка), затем 3–11 дней до комиссии.

**Периодичность:** каждый «Объект N» встречается **ровно один раз за год** —
ППР годовой, все 26 объектов покрыты одним календарным циклом. Дат — 2026 год,
и никаких других периодов в файле нет.

**Виды ремонтов:** один — «ППР аппаратуры контроля метана» (ремонт + поверка
датчиков). Никакой детализации работ (марки, узлы, объём) в этом файле нет —
марки оборудования (ГАСБ, МУСБ, УСЛБ-А, ПККГ, АС-9, МУИ, ИБП, кабельные линии АКМ/ДУ,
«к-р Ясенево») лежат в **соседнем** файле `График_ТО_АКМ_и_ДУ_на_2026г_РЭК_3_на_А4.xlsx`
(ТО и ТР на 2026 г., тот же подразделение «РЭК», тоже обезличенный) — он не входил
в задание и здесь не разбирался.

**Факт/отметки о выполнении: НЕТ.** Колонок «выполнено», «ответственный», «подпись»,
«факт» в файле нет вообще — это чистый план на будущее. Это согласуется с письменным
ответом заказчика 19.09.2026: «Данные по истории ремонтов, графикам работ и реестру
оборудования не переданы и предоставлены не будут» (сводный 7) — но сам **план** 25.09.2026
они прислали.

## 6. Сущности и привязка к нашим данным

**АКМ** — *аппаратура контроля метана* (расшифровка дана прямо в титуле файла).
**РЭК** — подразделение-владелец графика; расшифровки нет ни в файле, ни в наших
документах; по контексту — район эксплуатации коллекторов (в `smvu.object_tree` у нас
«1 район»). **ОМ** — организация, принимающая датчики на ППР и поверку (по контексту —
отдел метрологии/механизации).

**Идентификаторов для привязки к нашим данным в файле НЕТ.** Перечислено всё,
что есть в колонке «Наименование коллектора»: «Объект 1» … «Объект 26» — **заглушки-нумерация**,
без настоящих названий, номеров тегов, пикетов, адресов, участков, ID.

Сверка с `dataset/` и схемой:

| Наше | Значение | Сходится ли с файлом ППР |
|---|---|---|
| `smvu.channel` / справочник каналов | 11 485 каналов, теги `847-1.1.49.4.`, префиксы-коллекторы (32 шт.: 15, 257, 847, 1051…) | тегов в файле нет |

## 7. Ценность для ML-признаков

Что файл даёт семантически (после решения привязки):

1. **«Плановый ремонт в горизонте прогноза»** — окно `[демонтаж; сдача комиссии]`
   на объект, 13–25 дней. Формируется только на 2026 год.
2. **«Датчик(и) в плановом ППР» — самое ценное и для качества данных:** в окне
   датчики физически демонтированы (этап 1→3), значит канал молчит **по плану**,
   а не по отказу. Это фильтр/флаг для эпизодов отказов (`smvu.fault_episode`, метка D5):
   пропуск в окне ППР — не отказ, а ремонт; возврат из ОМ может давать всплеск показаний.
3. **«Фаза окна ППР»** (демонтаж / в ОМ на поверке / возврат / до комиссии).
4. **«Дней до следующего ППР»** — в пределах 2026 считается.
5. **Годовой цикл ППР** — каждый объект один раз в год (косвенный норматив для
   признака «выработка межремонтного интервала»), но дат прошлых лет файл не даёт.

Что НЕ получить:

* **«Дней с последнего ремонта» — не посчитать вообще:** нет истории (2019–2025),
  нет отметок о фактическом выполнении даже по 2026.
* **Обучающий признак на историю 2019–2026 невозможен** — см. критический вывод ниже.

### Критический вывод по покрытию

**Данные покрывают только 2026 год — 12.01.2026…22.12.2026, и это ПЛАН, а не факт.**
Исторических/повторяющихся сведений в файле нет (единственная косвенная зацепка —
годовая периодичность: объект 1 раз в год). Следствия:

* на историю 2019–2025 (и на окно обучения модели v3 — 2022-04-01…2026-03-31)
  признак **не посчитать и учить на нём нельзя** — единственный год покрытия не
  перекрывает историю, а «с последнего ремонта» не определено ни для одной даты;
* признак годен **только для инференса** — «плановый ППР в горизонте» после
  привязки объектов, и только для дат после получения графика (25.09.2026);
* пересечение графика с нашим журналом (край выгрузки **30.06.2026**) — пакеты
  P01–P09 (14 объектов из 26, **556** датчиков из 1 008): по ним можно ретроспективно
  проверить гипотезу «в окне ППР канал молчит» на 2019–2026 журнале — это валидация
  эффекта, а не обучающий признак. С окном обучения модели пересекаются только
  P01–P05 (7 объектов, 326 датчиков).

### Что запросить у заказчика, чтобы файл стал полезным

1. **Словарь «Объект N» → коллектор/тег/участок** (или настоящие названия коллекторов) —
   без него файл не связывается с `smvu.channel`/`smvu.object_tree`;
2. расшифровки «до 900», «РЭК», «ОМ»;
3. **отметки о фактическом выполнении** (факт ППР 2026) и **графики ППР 2019–2025** —
   только они дадут «дней с последнего ремонта» и обучающий признак.
