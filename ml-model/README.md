# Прогноз отказов датчиков

В продукте работают **правила датчика с горизонтом 24 часа**: давность последнего
подтверждённого отказа и, только в демонстрационном режиме с синтетикой, предвестник.
Worker читает `backend/app/domain/sensor_rules.json`. Обучение, протокол оценки и
команды повтора описаны в [sensor/README.md](sensor/README.md).

На реальных отказах апреля–июня 2026: Precision **0,120** (59/493), Recall **0,097**
(59/606). Пороги выбраны на январе–марте. Синтетические паспорта и предупреждения
служат демонстрации механики; их результаты не являются качеством на реальных данных.
Отказ здесь — потеря связи с каналом («Неисправен» дольше часа), а не установленная
причина поломки оборудования.

## Состав

- [sensor/](sensor/README.md) — обучение правил, сравнение с регрессией, выгрузка
  входных данных и результаты исторической проверки.
- `src/ml/reading_features.py` — очистка показаний метана и признаки вероятной
  поверки. Это заготовка для экспериментов; текущий worker эти признаки не использует.
- `src/ml/` — функции обработки журнала и библиотека чтения исследовательских весов.
- [models/lgbm-v3-bag-2026.09.21/](models/lgbm-v3-bag-2026.09.21/README.md) —
  сохранённые исследовательские веса модели коллектора v3 на **720 часов**.
  Она **не участвует в прогнозе диспетчера**. Её метрики нельзя приписывать правилам
  датчика на 24 часа. Старые команды обучения, архивного расчёта и Dockerfile этой
  модели исключены из поставки; веса и их контрольные суммы сохранены для проверки.
- `tests/` — проверки очистки показаний и контракта исследовательских весов.

## Запуск продукта и повтор расчётов

Сборка сервиса, импорт исходной выгрузки и запуск worker описаны в
[инструкции развёртывания](../deploy/README.md). Правила исполняются в backend,
отдельный контейнер модели коллектора для них не нужен.

Для повтора обучения нужны исходные данные заказчика в базе и выгрузка CSV:
команды приведены в [sensor/README.md](sensor/README.md). Данные заказчика в Git
не входят. Исторический замер не подтверждает качество на новых датах и объектах.

## Очистка показаний

Из корня репозитория, Python 3.12 или новее:

```sh
PYTHONPATH=ml-model/src python3 -m ml.reading_features \
  --channels dataset/справочник_каналов_датчиков.csv \
  --journal dataset/ext-journal-2025.csv dataset/ext-journal-2026.csv \
  --as-of 2026-07-01T00:00:00+03:00 --out /tmp/sensor-reading-features
```

Выход — `features.csv` и `audit.json`; формат описан в
[контракте](../contracts/sensor-reading-features.v1.json). Файлы входа должны
содержать полные сутки без перекрытия. При присоединении признаков к историческим
срезам требуется `available_at <= as_of`. Отсутствие строки не означает молчание
датчика: таблица охватывает газовые показания и отметки эпохи.

## Проверка чистого клона

Из корня репозитория, в отдельном окружении Python 3.14:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r ml-model/requirements/ml-test.txt
.venv/bin/python -m pytest ml-model/tests -q
PYTHONPATH=backend .venv/bin/python -m app.domain.sensor_risk
```

Тесты используют поставляемые веса и контрактные входы, включая пропуски значений;
клиентские данные для них не нужны. Это проверка кода и форматов, не повторная
оценка Precision/Recall. Контрольные суммы весов проверяются из их каталога:

```sh
(cd ml-model/models/lgbm-v3-bag-2026.09.21 && shasum -a 256 -c SHA256SUMS)
```
