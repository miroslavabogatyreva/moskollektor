# MOS-225: признаки показаний датчика, 28.09.2026

## Что изменилось

`ml-model/src/ml/reading_features.py` читает исходные CSV журнала и справочник
каналов. Для модели датчика он пишет `features.csv` и `audit.json`; запуск описан
в `ml-model/README.md`, поля — в `contracts/sensor-reading-features.v1.json`.
Готовый сжатый CSV и аудит лежат рядом с данными MOS-263 в
`docs/proof/2026-09-28-sensor-model/data/reading_features*`.

1. Для метана принимаются только конечные числа **0 ≤ x ≤ 15 % объёма**.
   Это выбранное командой правило качества по предложению Мирославы, а не предел
   достоверности измерения, названный заказчиком. Отрицательные, выше 15 и
   бесконечные/NaN значения исключаются из среднего, максимума и счётчика ≥ 1 %.
   Счётчики исключений сохраняются отдельно, исходный журнал не меняется.
   Превышение 1 % определяется по числу, даже если `тревожное = f`.
2. День с десятью и более газовыми каналами, показавшими **валидное** число ≥ 1 %,
   получает `calibration_candidate = 1`. Правило применяется к завершённым суткам,
   без медианы будущих дней. Текст `Обнаружен газ` сохраняется вместе с флагом:
   это не метка подтверждённой утечки. Решение Мирославы — не считать такие дни
   газовыми инцидентами — действует при будущей разметке этого направления;
   нынешняя задача не строит газовые метки. Флаг общий для дня и не доказывает
   поверку каждого канала. Контрольный газовый журнал заказчик не предоставил.
3. Обе строки `01.01.1970 03:00:0[01]` остаются полученными записями. В действующих
   признаках они уже не попадали в `Неисправен`/`Неопределен` и в D5. Добавлены
   проверки реального CSV-парсера, PostgreSQL-функции суточной свёртки и SQL
   ML-агрегатов. Уточнён устаревший комментарий парсера: `value_num = NULL`
   означает «не число», а не «показание отсутствует».

Тип берётся только из справочника **каналов**, не из справочника состояний.
D5, `smvu.fault_rule`, обученные веса и служебные запросы стенда не изменены.

## Причинность и границы применения

Сутки 23 июня доступны с `24 июня 00:00 +03:00`. В прогноз на 23 июня 21:00 они
не входят. CLI требует пояс у `--as-of` и отбрасывает текущие московские сутки
целиком; при чтении готовой таблицы нужно снова фильтровать
`available_at <= время решения`, затем выбирать историческое окно.

Таблица разреженная: все дни с записями газовых каналов и дни с отметками эпохи
на остальных каналах. `selected_rows` не является признаком активности всего
парка, `epoch_marker` служит аудитом, а отсутствие строки не означает молчание.
До января 2025 данных в поставляемом файле нет. Счёт идёт по исходным строкам
CSV, а не после дедупликации событий загрузчиком БД; входные файлы не должны
перекрываться. Повторная шапка склеенной выгрузки 2025 пропускается отдельно.

Признаки подготовлены для эксперимента MOS-263 после ревью MOS-264. Текущий
инференс этот файл не читает. Дополнительная проверка Precision не показала прироста при одинаковом бюджете
пяти предупреждений в сутки: см. `ml-model/docs/mos225-precision/README.md`.
Добавлять признаки в обученный вектор без повторного обучения нельзя.

## Проверка

- 166 тестов бэкенда и `code/tests` прошли с локальным PostgreSQL, 2 пропущены.
- ML-набор: 31 тест прошёл, 30 пропущены из-за отсутствия внешних исходных
  Parquet/артефактов прежней модели. Все новые проверки MOS-225 выполнены.
- Регрессия `backend/tests/test_epoch_readings_db.py`: реальный разбор CSV → COPY
  в изолированную PostgreSQL → функция миграции 022. Две записи сохранены,
  `readings_total = 2`, `fault_total = undefined_total = 0`, последнее время записи
  не потеряно. Проверочная БД удаляется после теста.
- ML-тесты проверяют границы 0/1/15, запятую, отрицательные, переполнение,
  нечисловые состояния, NaN/Inf, независимость от alarm, тип канала, повторную
  шапку, смену московской даты, отсутствие влияния будущего и исходные D5/агрегаты.
- Проверки схемы, комплекта выкладки, stale-fetch и selfcheck загрузчика прошли.
- Сырые CSV читались отдельным `nice -n 10` процессом с ограничением 600 секунд.
  На сервере записаны только временные артефакты задачи; БД и сервисы не менялись.

справочника: тип газа им не приписывается, отметки эпохи сохраняются, если есть.

Проверка готового артефакта (`test_published_features_match_customer_analysis`)
читает поставляемый gzip целиком, сверяет хеши, уникальность ключей, доступность
по времени, границы чисел, суммы исключений и независимый список 35 дней.
