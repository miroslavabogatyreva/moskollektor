# Отдельная история Local24, 2019–2020

23.09.2026 построен новый локальный набор `data/03_processed/local24_history_20192020_20260923`. Его можно использовать в заранее объявленном сравнении добавления старой обучающей истории к каноническому контролю 2022+, при неизменных evaluation-folds 2025. Этот артефакт не доказывает улучшение модели, не является новым holdout и не меняет ранее сохранённые эксперименты.

Исходный код: `scripts/ml_local24_history_build.py`. Агрегированные результаты, проверки и SHA-256 выходов: [history-build.json](history-build.json). Данные Parquet остаются локальными, не коммитятся. Успешный полный запуск: `/tmp/lct-local24-history-build-20260923.log`; пригодность к использованию отмечена в выходном `metadata.json` статусом `validated_for_predeclared_training_history_ablation_only`.

## Определение и сопоставимость

- Метка: новый наблюдённый onset D5 в `(t,t+24h]`, длительность строго больше часа; подтверждение через 3 601 секунду. Использованы исходные `failure_defs.EXT`, четыре значения `D5_VALUES` и порядок `(ts,ev)`, а не старые D0-метки исторического эксперимента.
- 84 826 эпизодов пересобраны из настоящих `j2019.parquet` и `j2020.parquet` с удалением точных исходных дублей штатным генератором. Будущие концы эпизодов цензурируются cutoff; незакрытые остаются открытыми.
- Дневные признаки взяты из `autoresearch_hist_20260915/chanday.parquet` только за 2019–2020. Его 533 049/686 322 channel-days содержат ровно 20 993 328/28 172 398 исходных записей, как сырые журналы. Дополнительно все использованные дневные счётчики сверены с независимой сырой пересборкой в двух временных префиксах.
- Имена всех 40 признаков и порядок всех колонок `dataset.parquet` точно совпадают с первоначальным Local24. `short_7d`/`short_28d` имеют **каноническую исправленную семантику**: после цензуры закрытия — точная дедупликация кортежа и `0<duration<=1h`. Поэтому сравнивать надо с таким же исправленным short-контролем 2022+, не со старыми нулевыми эпизодами под теми же именами. Sensor-only признаки сюда не подмешиваются.
- Разрешённый продуктовый mapping и правила exclusion/exposure/global past coverage/target completeness те же. Реестр считается текущим и условно переносится назад; историческая точность расположения не доказана.
- 2021 не читается ни для меток, ни для признаков, ни для прогрева. Набор 2022+ не пересобирается и не получает состояние из 2020. Cutoff 31.12.2020 23:59:59 и требование полного окна `t+25h` исключают хвост перед разрывом.

Изолированная копия модуля календаря загружается в выделенном процессе с origin 01.01.2019; файл и обычный модуль `ml.local24_data` не меняются. Исторический `_prepare` явно отделён от замороженного warmup 2022. Методы расчёта признаков, событий и riskset наследуются от действующего section-builder. Ресурсы каждого последовательного прохода: четыре потока DuckDB, 8 ГБ.

## Проверки на реальных данных

Перед сборкой проверены повторяющиеся `(ch,ts,ev)`. В 2019 найдена 1 491 повторная группа, в 2020 — ноль. Смешанных true/false D5-состояний при одном ключе нет в обоих годах. NULL в этой проверке трактуется как не-D5. При конфликте скрипт прекращает построение, а не выбирает состояние произвольно.

На 01.07.2019 и 01.07.2020 заново построены эпизоды и дневные счётчики **только из сырого журнала до данного момента**. Для 12 реальных участков с событиями, по одному на соответствующий коллектор, все 40 признаков совпали точно с расчётом из полного исторического архива. Дневные счётчики полного доступного префикса по всем каналам также совпали: ноль расхождений. Это проверка доступности информации во времени, не верификация физической идентичности канала.

После сборки проверены: ноль повторов `(section_id,as_of)`, ноль повторных long-event IDs, ноль строк 2021 года, ноль неполных target+confirmation-окон в eligible-наборе, ноль противоречий между `y` и `n_events>0`. Список признаков и порядок колонок совпадают с исходным Local24.

В сумме теряется 665 из 3 487 длинных эпизодов ещё при пространственной привязке; из 2 822 привязанных остаётся 1 944 события в допустимом daily risk set. Это не основание автоматически выбрасывать всю историю, но ограничение интерпретации эффекта её добавления. Несколько каналов могут дать события на одном участке в один день: 1 944 события не равны 1 944 независимым положительным дням.

До января 2019 прогрева нет. Первое сообщение не доказывает дату установки и может быть первым наблюдением уже существовавшего состояния. Текущие участки, диапазонные ПК, смена оборудования и неизвестные ID остаются ограничениями из [mapping-audit.md](mapping-audit.md). Успешный prefix-check не устраняет их.

## Воспроизведение

```sh
PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=4 \
  /usr/local/anaconda3/bin/python3 scripts/ml_local24_history_build.py \
  --root /Users/Nik/Projects/lct-2026-task8 \
  --output /Users/Nik/Projects/lct-2026-task8/data/03_processed/local24_history_20192020_20260923
```

Команда откажется перезаписывать существующий каталог. Для независимого повтора указать новый пустой путь. `metadata.json` появляется только после всех prefix-checks; наличие одних Parquet до успешной проверки не означает готовность набора. Скрипт не обучает модели и не использует оценки на 2025 для настройки меток или признаков.
