# Отдельная канонизация истории эпизодов V3

V2 зафиксирована коммитом `c76c534`, её модуль и выход не изменены. Эта версия —
отдельная гипотеза исправления качества входа, сформулированная после серии V2.
Она не означает улучшения метрик и не выбирается по результатам 2026 года.

## Правило

В `src/ml/local24_sensor_features_v3.py` сначала отбираются начала, доступные к моменту
наблюдения, и скрываются будущие `t_end` вместе с `close_val`. Затем удаляются только
**известные** неположительные интервалы. Строки с неизвестным концом сохраняются.
После этого удаляются точные копии `(ch,t_start,t_end,close_val)`. Остаточный конфликт
по `(ch,t_start)` приводит к ошибке, а не к выбору самого длинного/короткого будущего эпизода.

На полном источнике и двух исторических срезах конфликтов после этого правила нет.
Такое правило сохраняет уникальные положительные интервалы, которые V2 консервативно
теряла вместе с неоднозначной группой. Из **143** длительных исходных эпизодов восстановлены
**134** на допустимых пикетных участках. У остальных девяти нет `section_id`; два из них
вообще отсутствуют в актуальном справочнике каналов. Они не включаются искусственно.

Новое правило по-прежнему применяется к архивным представлениям эпизодов. Полная
эквивалентность историческим онлайн-входам требует контроля задержек поступления и версий
журнала. Дополнительно выполнен ограниченный независимый контроль восстановления из сырого
журнала — это усиливает проверку, но не доказывает всю эксплуатационную цепочку.

## Выход и неизменность протокола

`data/03_processed/local24_sensor_20260923_v3/sensor_features.parquet`:

- **4 267 349** исходных допустимых ключей `section_id,as_of`.
- **63** признака. Все **42** признака V2, не зависящие от эпизодов, совпадают точно.
- Изменения по 19 прежним признакам эпизодов перечислены в `metadata.json`.
- Добавлены `sensor_valid_short_count_7d` и `sensor_valid_short_count_28d` — число
  закрытых положительных эпизодов длительностью не более часа, известных к прогнозу.
- Исходы, разметка, экспозиция и даты оценки остаются прежними.

SHA-256: `d441d66fc3e3a8bca3db9148e87bc9f82928dab73dcc64ed52ad1a7ce1b5319a`.

Примеры затронутых строк относительно V2: счётчик подтверждённых каналов за 28 дней —
455; повторных коротких эпизодов по каналам за 28 дней — 148 928; давность закрытия —
250 137. Большие различия в короткой истории не следует выдавать за эффект лишь добавления
одного признака. Запланированная проверка заменяет ошибочные исходные `short_7d/short_28d`
каноническими счётчиками и использует V3-историю: это **вариант исправления входных данных**.
Новые счётчики не должны второй раз включаться в модель после замены исходных колонок.

## Проверки

Команда:

```
LOCAL24_ROOT=<main-root> PYTHONPATH=src python -m pytest tests/ml/test_local24_sensor_features_v3.py -q
```

**5 проверок прошли за 2,89 секунды**:

1. Все признаки совпали точно между полным и обрезанным архивом на 15.05.2025.
2. То же на 15.05.2026.
3. Счётчики положительных коротких эпизодов совпали с независимой агрегацией известных закрытий.
4. Реальный продолжавшийся эпизод с скрытым будущим концом сохранён как неизвестно закрытый.
5. Для двух реальных каналов с повторяющимися началами эпизоды независимо восстановлены
   из `j2022..j2026.parquet` существующим сборщиком `failure_defs.build_episodes`.
   Канонизация полного восстановления после цензурирования совпала точно с восстановлением
   из исходных записей только до 15.05.2025 и только до 15.05.2026.

Сравнение всей матрицы V3 с V2 отдельно проверило ключи и все неэпизодные признаки;
сборщик прекращает работу при любом таком расхождении. Полный пересчёт ограничен четырьмя
потоками и 8 ГБ DuckDB, записи в чужие датасеты и внешние сервисы отсутствуют.
