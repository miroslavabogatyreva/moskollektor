# Как поднять стенд

Полная инструкция по развёртыванию на сервере заказчика — `docs/install.md`, она пишется
в блоке Q9 (MOS-78). Здесь только то, что нужно, чтобы стенд заработал на своей машине.

Проверено 15.09.2026 с нуля дважды. Второй прогон — после того, как nginx научили
адресам нового вида, а `check-tls.sh` — четвёртому вердикту: стенд снесли вместе
с томами, удалили `.env` и `nginx/certs`, прошли три шага ниже и получили оба
контейнера `healthy` за 12 секунд. Каждая команда из этого файла прогнана и отвечает
тем, что здесь написано, — включая оба протокола замера TLS.

## Что должно стоять на машине

Docker с плагином `compose` — тем, который пишется через пробел, а не старый
`docker-compose` через дефис: файл `docker-compose.yml` написан под плагин.
Проверить:

```
docker --version          # у нас работало на 29.6.2 и 29.8.0
docker compose version    # у нас 5.3.1 на маке и 5.5.1 на сервере
docker info               # демон должен отвечать, а не ругаться на сокет
```

На маке с Apple Silicon перед этим надо запустить Docker Desktop, иначе `docker info`
напишет `connect: no such file or directory` и ничего не поднимется.

## Три шага, все обязательные

Выполнять из каталога `deploy`.

**1. Завести файл переменных.** В git его нет, у нового человека его не будет.

```
cp .env.example .env
```

Дальше открыть `.env` и заменить `POSTGRES_PASSWORD=СМЕНИ-МЕНЯ` на настоящий пароль.
Пропустить этот шаг нельзя: без `.env` compose подставит пустые строки, база откажется
разворачиваться и напишет в журнал `You must specify POSTGRES_PASSWORD to a non-empty
value for the superuser`.

**2. Выпустить самоподписанный сертификат.** Его в git тоже нет.

```
sh make-cert.sh
```

Скрипт кладёт `server.crt` и `server.key` в `nginx/certs`. Пропустить нельзя: nginx
не стартует и напишет `cannot load certificate "/etc/nginx/certs/server.crt"`.

**3. Поднять стенд.**

```
docker compose up -d
```

**Если запустили не в том порядке.** `docker compose up -d` без шагов 1 и 2 поднимет
контейнеры, и они тут же упадут: база — на пустом пароле, nginx — на отсутствующем
сертификате. Каталог `nginx/certs` при этом появится пустым, его создаёт докер сам под
точку подключения — не принимайте это за сделанный шаг 2. Выход: `docker compose down`,
потом шаги 1 и 2, потом `up -d` заново.

## Убедиться, что поднялось

**Команда `docker compose up -d` возвращает 0, даже когда обе службы падают сразу
после старта.** Она сообщает, что контейнеры созданы и запущены, а не что процессы
внутри них работают. Поэтому проверять надо отдельно:

```
docker compose ps
```

Оба контейнера должны дойти до `(healthy)`: база примерно за 20 секунд, nginx
примерно за 15. Пока стоит `(health: starting)` — ещё рано делать выводы.

Дальше проверить, что сервер отвечает:

```
curl -sk -o /dev/null -w '%{http_code} %{http_version}\n' https://127.0.0.1/   # ждём: 200 2
curl -sk -o /dev/null -w '%{http_code} %{http_version}\n' 'https://[::1]/'     # ждём: 200 2
curl -s  -o /dev/null -w '%{http_code}\n' http://127.0.0.1/                    # ждём: 301
curl -s  -o /dev/null -w '%{http_code}\n' 'http://[::1]/'                      # ждём: 301
```

Адреса здесь написаны цифрами нарочно. Имя `localhost` на этой машине разворачивается
в два адреса, и какой из них возьмёт программа — зависит от программы: `curl` сегодня
уходит в `::1`. Проверив по имени, вы проверите один вход из двух и не будете знать,
какой. Квадратные скобки вокруг `::1` обязательны, иначе `curl` примет двоеточие
внутри адреса за отделитель порта.

Сертификат самоподписанный, поэтому `curl` без `-k` откажется с ним работать — это
ожидаемо, а не поломка.

База отдельной командой, пароль для неё не нужен:

```
docker compose exec -T db pg_isready
# ждём: /var/run/postgresql:5432 - accepting connections
```

**Зайти в базу запросом.** Имя пользователя и имя базы — не `postgres` и не `mos`: они
задаются в `.env` переменными `POSTGRES_USER` и `POSTGRES_DB`, и в `.env.example` там
стоит `moskollektor`. Скопировав команду с другим именем, вы получите
`role "mos" does not exist` при полностью исправной базе:

```
docker compose exec -T db psql -U moskollektor -d moskollektor -c '\dn'
# ждём: 12 строк. Наших девять — asset feat geo load maint permit pred ref smvu;
# ещё три служебные: public, а также tiger и topology, их заводит PostGIS
```

Накатить файл схемы или сида:

```
docker compose exec -T db psql -U moskollektor -d moskollektor -f /dev/stdin < ../db/migrations/006_explain_templates.sql
```

## Замер TLS для приёмки

Строку НФ-75 закрывает отдельный скрипт, его вывод и есть протокол:

```
sh check-tls.sh 127.0.0.1 > ../docs/protocol-tls-ipv4.md
sh check-tls.sh ::1       > ../docs/protocol-tls-ipv6.md
```

Протокола два, и оба обязательны: nginx слушает оба вида адресов, а закрыт правильно
может оказаться только один — по одному файлу этого не увидеть. В один файл писать
нельзя, второй прогон затрёт первый.

Нужен `nmap`: на маке `brew install nmap`, на сервере `apt-get install nmap`.
Что должно получиться: секции TLSv1.2 и TLSv1.3 с тремя наборами в каждой, секций TLSv1.0 и TLSv1.1 нет вообще, а у форсированных
подключений `-tls1` и `-tls1_1` в строке «Итог» стоит «СЕРВЕР ОТКЛОНИЛ».

## Снести стенд

```
docker compose down       # убирает контейнеры, данные базы остаются в томе
docker compose down -v    # убирает и тома, база стирается насовсем
```

Данные переживают и `restart`, и `down` без `-v` — проверено 15.09.2026 на таблице
из трёх строк: после пересоздания контейнера строки остались с прежними метками времени.
