# Обучение и проверка MOS-264

Текущий артефакт: `sensor-lr-h12-tick-frozen-2026.09.28`, горизонт **12 ч**, SHA-256 `2e1492bd8bc2c6f1c33206a88c9cfad58e809cffbb835f2a56fd5eb733262f13`.

Оба режима обязательны: без синтетики — журнал D5; с синтетикой — реальная ветвь плюс модель синтетического паспорта и предвестников. Расчёт, API и переключатель сохраняются. Результаты — [metrics.md](metrics.md).

## Данные и время

Файлы `data/*.csv` описаны в README, их полные суммы сохранены в `run.json → metadata.input_sha256`. Обучение 01.04.2022–31.12.2025; выбор горизонта и порога январь–март 2026; ретроспективная проверка апрель–июнь. Апрель–июнь ранее анализировались, поэтому независимость финальной проверки не заявляется.

Метка — начало следующего эпизода D5 длительностью строго больше часа, плановый демонтаж газа исключён. Собственная история и соседние каналы становятся доступными только через 3601 с. Для будущего исхода используется строгое окно `(t, t+H]`, а не уже начавшийся эпизод. Точность времени архива — секунды. Известность записи по времени её поступления восстановить нельзя.

Расписание оценки — раз в сутки, 21:00 МСК. Отдельные расчёты rearm не поставляются как поведение worker. Граница окон обрезается до полного горизонта с консервативным исключением последнего дня. Точные срезы и знаменатели — `run.json`.

## Модель и экспорт

Логистическая регрессия: real — давность и количества подтверждённых эпизодов, соседние события, вид датчика; sim — возраст к сроку службы, интервал/просрочка поверки и четыре возрастные корзины искусственных предупреждений. Признак свежего подтверждённого эпизода real сохранён с единым коэффициентом, но отдельная событийная политика не применяется.

В обучение входят все положительные строки и 10% отрицательных с весом 10, seed=263. Горизонты 12/24/36/48 выбираются по F1 real на Q1; затем тот же H применяется обеим ветвям. Пороги каждой ветви выбраны на Q1 между различными значениями балла. **Коэффициенты после выбора не переобучаются**, перенос порогов с другой модели отсутствует. В JSON сохраняются полные float, проверяются и вероятности, и решения high/watch на всех строках Q1/Q2. Дополнительная проверка публичной функции score и объединения ветвей — `combined_demo.py`.

Runtime использует только стандартную библиотеку Python. Scikit-learn нужен для обучения, в образ приложения новая зависимость не добавляется. HTTPX добавлен только в requirements-dev для интеграционных тестов.

## Воспроизведение

Среда выполненного расчёта: Python 3.13.9, NumPy 2.3.3, pandas 2.3.3, scikit-learn 1.7.2; точные версии остальных зависимостей — `../2026-09-28-mos264-review/environment.txt`.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1 \
  .venv/bin/python -u docs/proof/2026-09-28-sensor-model/train_sensor_model.py \
  > docs/proof/2026-09-28-sensor-model/run.log 2>&1
shasum -a 256 -c docs/proof/2026-09-28-sensor-model/SHA256SUMS
.venv/bin/python docs/proof/2026-09-28-sensor-model/combined_demo.py
```

Повторять из корня репозитория. Полный прогон занимает около 71 с на использованном Mac; это не оценка времени стенда. SHA входов, исходников и модели записаны в run.json. Автоматические проверки до экспорта останавливают прогон при несовпадении признаков или решений.

## Границы результата

По реальному архиву нет преимущества над давностью. Синтетический расчёт работает и полезен для демонстрации детализации до датчика, но его результат зависит от выдуманных паспортов и механизма P-F. Приёмка М-18…М-20 остаётся на существующей модели коллектора v3. Развёртывание и проверка на общем стенде выполняются после рассмотрения PR в рабочую ветку; локальная проверка не означает принятия стенда.
