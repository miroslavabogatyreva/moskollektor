Составлено 15.09.2026. Файл отвечает на два вопроса: **где искать** и **куда положить**.

## Главная связка: каталог = блок работ

Работа нарезана на десять блоков, и **граница блока совпадает с каталогом**. Это
не совпадение, а правило: открыв блок в трекере, видно, куда упадёт код; открыв каталог,
видно, из какого блока он вырос.

| Блок | Каталог | Что внутри | Есть сейчас |
|---|---|---|---|
| `Q0` Вопросы к заказчику | — | письма, живут в переписке и в `analysis/` | частично |
| `Q1` Развёртывание | `deploy/` | compose, nginx, TLS, бэкапы, нагрузочный прогон | нет |
| `Q2` Данные | `db/`, `backend/app/ingest/`, `backend/app/archive/` | миграции, справочники, загрузчик, архив | прототипы в `code/` |
| `Q3` Расчётное ядро | `backend/app/worker/` | восемь стадий, планировщик, сборка признаков | прототипы в `code/` |
| `Q4` API и доступ | `backend/app/api/`, `backend/app/auth/` | девять методов, роли, журнал действий | нет |
| `Q5` Интерфейс | `frontend/` | дашборд, схема коллектора, журнал | макет в `dashboard/` |
| `Q6` Заявки | `backend/app/domain/`, `frontend/src/screens/orders/` | автозаявка, пороги, переходы | схема в `code/` |
| `Q7` Граница с ML | `contracts/`, `backend/app/mlclient/` | контракт, версии, вызов модели | нет |
| `Q8` Модель | репозиторий Николая | обучение, метрики, объяснимость | нет |
| `Q9` Приёмка | `docs/`, `delivery/` | документы сдачи, протоколы, замеры | `docs/` есть |

**Правило для нового файла одно: найди свой блок, положи в его каталог.** Если файл
не ложится ни в один — либо блок назван неверно, либо файл лишний.

## Четыре правила, которые легко нарушить

**Первое: `code/` — не продукт.** Там прототипы и считалки с самопроверками.
Продуктовый код живёт в `backend/`, `frontend/` и `db/`. Когда загрузчик
`backend/app/ingest/smvu_csv.py` поедет в `backend/app/ingest/`, в `code/` он останется только
если полезен как самостоятельная утилита.

Пять схем базы этот путь уже прошли: 15.09.2026 задачей `Q2.1` они уехали
из `code/schema_*.sql` в `db/migrations/001_assets.sql` … `005_xref.sql`, и в `code/`
копий не осталось. Копии я не оставила намеренно — две копии одной схемы разъедутся,
а поймать расхождение будет нечем. `code/check_schema.py` теперь читает миграции,
а не соседние файлы.

**Второе: `dataset/` в git не идёт, выгрузка живёт на сервере.**
Путь `/srv/moskollektor-hakaton-data/dataset` на `135.106.216.101`, команда
для копирования — в `docs/server.md`. Шестнадцать гигабайт,
и в репозиторий мы их не кладём, правило
в `.gitignore`. Промежуточные Parquet (3,3 ГБ) тоже не идут — они пересобираются
скриптами из `analysis/` за пять минут.

Там же, на сервере, с 15.09.2026 лежат PDF книг — `/srv/moskollektor-hakaton-data/books`,
десять файлов на 101 МБ, правило `docs/books/*.pdf`. Наши разборы книг
(`docs/books/*.md`) остаются в git: то, что мы написали, — в репозитории, то,
что мы скачали, — на сервере.

**Третье: контракт живёт у нас, а не у ML-команды.** Перед заказчиком за приёмку
отвечаем мы, поэтому файлы `contracts/` лежат в нашем репозитории. Николай забирает
их по тегу и открывает PR, когда ему нужен новый признак. Обоснование —
`docs/HLD.md` разд. 2.

**Четвёртое: ссылки на файлы пишем от корня проекта.** `docs/HLD.md`,
`db/migrations/004_events.sql`, а не `../code/` и не `./HLD.md`. Так ссылка читается
одинаково из любого файла и не ломается при переносе.
