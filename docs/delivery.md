## Пакет сдачи

**Как собрать:** `bash delivery/pack.sh --check` из корня репозитория. Скрипт кладёт
архив в `dist/moskollektor-<версия>.tar.gz`, где версия — `git describe`, то есть тег
`v1.0`, когда его поставит задача `Q9.7`. Собирает он из закоммиченного `HEAD`
командой `git archive`, а при незакоммиченных правках отказывается собирать.

**Что внутри.** Всё, что лежит в git, кроме трёх каталогов. `final-presentation/`
(68 МБ) сдаётся своей ссылкой, настройки агентов и `.claude/` — настройки разработки.
Выгрузки заказчика в пакете нет, она у заказчика своя, а заливка описана в
`docs/install.md` разд. 5. Весов модели v3 тоже нет: их отдаёт ML-команда,
а без них сервис считает заглушкой `ml-stub/` (`docs/data-processing.md` разд. 6).

**Замер 28.09.2026 на коммите `06bab12`:** архив весит 36 МБ (38 428 054 байт),
а без исключений было бы 105 МБ. Проверка распаковкой зелёная: 15 обязательных файлов
и каталогов на месте, ни `dataset/`, ни `final-presentation/`, ни `deploy/.env` в
архиве нет, `code/check_schema.py` отвечает «проблем нет», а `docker compose config`
разбирает файл со всеми профилями. Из распакованного каталога проходят 10 проверок
из 11 пакетных (`docs/install.md` разд. 8). Одиннадцатая, `check_structure`, сверяет
счётчики с `git ls-tree`, а `.git` в архиве нет, поэтому её запускают только из клона.

**Чего проверка не делает.** Стенд из архива она не поднимает: для этого нужны
демон Docker и выгрузка заказчика, а в облачной сессии, где собирался архив, нет
ни того, ни другого. Подъём с нуля по `docs/install.md` на чистой машине —
последняя половина строки НФ-83, её делает человек, который решение не писал.
