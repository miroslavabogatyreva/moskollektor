## Правило организаторов, которое нельзя нарушать

Слайды 7–11 шаблона обязательные, и их дизайн менять нельзя: ни сетку, ни положение
блоков, ни оформление. Меняем только текст. Единственное исключение — слайд команды:
лишние карточки участников можно удалить, что мы и сделали, оставив две из пяти.
Остальные слайды — наша описательная часть, там свобода.

## Как вносить правку

**Сначала проверь, не правила ли Слава файл руками.** 28.09.2026 она вставила
в PowerPoint фото на слайд 2 (фигура `Рисунок 2`), а скрипт про фото ничего
не знает: пересборка путём 1 их сотрёт. Проверка — `git diff --stat
docs/final-presentation/presentation.pptx` и сравнение текста через `markitdown`
с версией из git. Есть ручные правки — правь готовый файл путём 2 или спроси Славу.

Есть два пути. Какой выбрать, зависит от того, есть ли у тебя шаблон.

**Путь 1: пересобрать из шаблона. Основной.** Все тексты лежат в `src/build.py`:
данные о людях — в словаре `TEAM` в начале файла, остальное — в блоке своего слайда.
Правишь текст в скрипте и собираешь заново:

```bash
python docs/final-presentation/src/build.py "ЛЦТ2026 Шаблон презентации.pptx" docs/final-presentation/presentation.pptx
docs/final-presentation/src/topdf.sh docs/final-presentation/presentation.pptx docs/final-presentation/presentation.pdf
```

Нужны `python-pptx` и `Pillow`. В `.venv` проекта их нет, ставь в отдельное
окружение и в `requirements` не добавляй: это инструмент для одного документа,
а не зависимость продукта.

**Путь 2: поправить готовый pptx. Когда шаблона нет — например, в облаке.** Открываешь
`presentation.pptx` через `python-pptx`, находишь фигуру по тексту и меняешь текст
у рана, а не у всей фигуры: `run.text = "..."` сохраняет шрифт, цвет и размер,
а `text_frame.text = "..."` сбрасывает оформление к бледной подсказке макета.
После такой правки внеси то же изменение в `src/build.py`, иначе следующая
пересборка его сотрёт.

## Где спотыкаются

- **Текст в плейсхолдерах макета по умолчанию бледный.** Это подсказка «впишите сюда»,
  и на белой карточке её почти не видно. Поэтому функция `set_text()` в скрипте
  ставит цвет явно: тёмный `1C1D22` для текста, фиолетовый `520978` для заголовков
  карточек, малиновый `FF0053` для номеров. Новый текст — только через неё.
- **Плашка под заголовком не растягивается сама.** Её ширину считает функция `title()`
  по длине заголовка. Если заголовок вылез за плашку, поправь коэффициент там.
- **`insert_picture` обрезает картинку под пропорции рамки.** Поэтому скриншоты
  заранее обрезаются функцией `crop()` под соотношение рамки браузера, 1,8 к 1,
  а логотипу размер задан явно — без этого у него получалась нулевая высота.
- **Длинный ник рвётся посередине строки.** Ник `@miroslavabogatyreva` набран на
  10 пт вместо 11, а текстовое поле в карточке расширено до 2,2 дюйма.
- **Всё, чего мы не знаем, пишем в квадратных скобках.** Скрипт красит такие куски
  малиновым, чтобы они бросались в глаза. В сданной презентации скобок быть не должно.

## Как проверить правку

Смотреть надо картинкой, а не чтением кода: переполнение и наезд текста на линии
видны только на отрисованном слайде.

```bash
docs/final-presentation/src/topdf.sh docs/final-presentation/presentation.pptx /tmp/p.pdf
pdftoppm -jpeg -r 80 /tmp/p.pdf /tmp/slide      # потом открыть каждый /tmp/slide-NN.jpg
markitdown docs/final-presentation/presentation.pptx | grep -o '\[[^]]*\]' | grep -v png
```

Последняя команда выводит оставшиеся квадратные скобки. Пустой вывод означает,
что заполнено всё.

`topdf.sh` работает только там, где стоит PowerPoint, то есть на Маке у Славы.
LibreOffice на этом Маке нет. В облаке отрисовать слайды нечем, и тогда в отчёте
надо прямо написать, что правка визуально не проверена.

PDF пересобирается после каждой правки pptx: сдаём оба файла, и они не должны
расходиться.
